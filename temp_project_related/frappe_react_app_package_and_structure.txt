- React

- JavaScript
- Vite
- frappe-react-sdk

- @reduxjs/toolkit
- react-redux

Routing:
- react-router-dom

UI / Design:
- @mui/material
- @emotion/react
- @emotion/styled
- @mui/icons-material
- @mui/x-data-grid
- @mui/x-date-pickers

Charts / Dashboard:
- recharts
- @mui/x-charts (OPTIONAL; use either Recharts or MUI X Charts as the primary chart library)

Notifications:
- react-hot-toast

Forms / Validation:
- react-hook-form
- zod
- @hookform/resolvers

Dates:
- dayjs

Utilities:
- clsx
- lodash-es
- lucide-react (OPTIONAL; use MUI icons OR Lucide consistently, not both everywhere)

Authentication / Cookies:
- DO NOT add a cookie package initially.
- Frappe's normal session authentication is cookie-based and frappe-react-sdk handles authentication.
- If you have a specific requirement to manipulate non-HttpOnly client cookies, add js-cookie later.
- Never store Frappe passwords, API secrets, or sensitive session tokens in localStorage.

Performance / Data:
- frappe-react-sdk already uses SWR internally.
- Prefer frappe-react-sdk hooks for Frappe API/database operations instead of adding Axios separately.
- Do not add React Query/TanStack Query unless there is a concrete requirement to manage a separate non-Frappe data source.

Optional advanced packages:
- socket.io-client (only if directly needed; frappe-react-sdk already provides realtime support)
- react-error-boundary
- date-fns (choose this OR dayjs, not both)
- xlsx (only if client-side Excel export is required)
- file-saver (only if browser-side file downloads are required)
- papaparse (only if CSV parsing/export is required)
- @dnd-kit/core, @dnd-kit/sortable (only if drag-and-drop dashboards are required)

3. WHAT EACH PACKAGE IS FOR

react / react-dom
- Application framework and browser rendering.

vite
- Fast development server and production bundler.

typescript
- Type safety for ERP data, API responses, forms and components.

frappe-react-sdk
- Main connection layer between React and Frappe.
- Authentication.
- Get/list/count documents.
- Create/update/delete documents.
- Whitelisted method calls.
- File uploads.
- Search.
- Realtime support.
- Prefer this instead of writing Axios calls throughout the frontend.

@reduxjs/toolkit + react-redux
- Global application state.
- UI state.
- User/session-related frontend state.
- Filters/preferences that genuinely need global state.
- Avoid putting every API response into Redux; use frappe-react-sdk/SWR for server state.

react-router-dom
- SPA routing.
- Protected routes.
- Nested layouts.
- Route-level pages.

@mui/material + Emotion
- Main responsive component system.
- Cards, grids, dialogs, forms, tables, drawers, menus, tabs, etc.

@mui/icons-material
- Consistent Material icons.

@mui/x-data-grid
- ERP-style tables.
- Sorting, filtering, pagination, column visibility, row selection.
- Particularly useful for Stock Balance, Sales, Purchase, Customers, Suppliers, etc.

@mui/x-date-pickers
- Professional date/month/year/range selectors.

recharts
- Dashboard charts.
- Line, bar, area, pie/donut, composed charts.
- Good fit for ERP dashboards.

react-hot-toast
- Success/error/info notifications.
- Use for save/update/delete/API feedback.

react-hook-form + zod + @hookform/resolvers
- Fast forms.
- Validation.
- Typed form schemas.
- Useful for filters and custom ERP forms.

dayjs
- Lightweight date handling.
- Good for ERP reporting periods and date filters.

clsx
- Conditional CSS/class composition.

lodash-es
- Useful utility functions where needed. Do not import the entire lodash package.

4. IMPORTANT ARCHITECTURE DECISION FOR FRAPPE REPORTS

Do NOT try to reproduce every ERPNext report entirely in React.

Recommended architecture:

React UI
    |
    +-- frappe-react-sdk
    |
    +-- Frappe REST / whitelisted Python methods
    |
    +-- ERPNext / Frappe database

For reports such as:
- Stock Balance
- Stock Ledger
- General Ledger
- Trial Balance
- Accounts Receivable
- Accounts Payable
- Sales Register
- Purchase Register
- Item-wise Sales
- Customer-wise Sales

Create backend Python API methods that call/reuse the appropriate Frappe/ERPNext report logic.

Return structured JSON such as:

{
    "columns": [...],
    "data": [...],
    "summary": {...},
    "chart": {...}
}

React should be responsible for:
- Filters
- Date range
- Company
- Warehouse
- Item
- Customer
- Supplier
- Pagination
- Sorting
- DataGrid display
- Charts
- Export
- Print/PDF UI

Backend should be responsible for:
- Database queries
- ERPNext report calculations
- Permissions
- Business rules
- Large-data aggregation

This keeps the frontend fast and avoids duplicating ERPNext accounting/business logic.

Tables:
- Recent Sales
- Recent Purchase Invoices
- Low Stock Items
- Overdue Receivables

Use responsive MUI Grid and cards so the dashboard works on desktop, tablet and mobile.

7. COLOUR / DESIGN SYSTEM

Use a bright professional palette rather than random colours throughout the application.

Example semantic colours:
- Primary: blue/indigo
- Secondary: purple
- Success: green
- Warning: amber/orange
- Error: red
- Info: cyan/blue
- Background: very light neutral
- Cards: white

Important:
- Define colours centrally in theme/colors.ts.
- Do not hard-code colours in every component.
- Use semantic colours consistently.
- Support light theme first.
- Keep the theme ready for dark mode.

8. RESPONSIVENESS

Build mobile-first.

Desktop:
- Permanent sidebar
- Dense dashboard
- Multi-column KPI cards
- Large report tables

Tablet:
- Collapsible sidebar
- 2-column cards
- Responsive filters

Mobile:
- Drawer navigation
- 1-column cards
- Horizontal/stacked filter controls
- Tables with controlled horizontal scrolling or mobile-specific card presentation
- Bottom/action buttons where appropriate

10. REDUX RULE

Use Redux for:
- Authentication/UI state
- Sidebar state
- Theme/preferences
- Global filters if genuinely shared
- User preferences

Do NOT use Redux as the primary cache for every Frappe document/report.

Use frappe-react-sdk/SWR for server data.

11. SECURITY

- Keep business logic and permission checks on the Frappe backend.
- Do not trust frontend permissions for authorization.
- Use Frappe session authentication where possible.
- Do not expose API secrets in Vite environment variables.
- Do not put sensitive credentials in localStorage.
- Validate filters and permissions on the server.
- Use whitelisted backend methods for custom reports.

16. IMPORTANT FRAPPE INTEGRATION NOTE

Frappe's app structure is still Python-based, and the app's package.json is used for Node dependencies. The React frontend can live inside a frontend directory within the Frappe app.

For development, use Vite to proxy requests to the Frappe site.

For production, build the React frontend and serve the generated assets through the Frappe app/public or the chosen Frappe frontend integration strategy.
